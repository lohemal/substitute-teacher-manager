## 1. 서명 키 — 가장 중요한 파일

```
%USERPROFILE%\.bogyeol-release\
  bogyeol-updater.key        ← 개인 키. 절대 공개하지 마세요
  bogyeol-updater.key.pub    ← 공개 키. 앱 안에 들어 있습니다
  PASSWORD.txt               ← 개인 키의 비밀번호
```

이 열쇠 한 쌍이 "이 업데이트는 내가 만든 것이 맞다"를 증명합니다. 앱은 이
개인 키로 서명된 파일만 설치합니다.

- **잃어버리면** 이미 설치된 프로그램에 업데이트를 보낼 수 없습니다.
  새 키로 만든 설치 파일을 사람들이 직접 다시 설치해야 합니다.
- **남에게 넘어가면** 그 사람이 만든 파일이 우리 프로그램인 척 설치될 수 있습니다.

그래서 이렇게 해 두세요.

1. `.bogyeol-release` 폴더를 **USB나 개인 클라우드에 복사해 보관**하세요.
2. **저장소에 올리지 마세요.** `.gitignore` 가 `*.key` 를 막고 있지만,
   폴더 자체를 프로젝트 밖에 둔 것이 더 확실합니다.
3. 메신저나 메일로 보내지 마세요.

### 키를 새로 만들어야 한다면

지금 키에는 비밀번호가 붙어 있습니다. 키를 새로 만들면
**이미 배포한 버전의 사용자들은 자동 업데이트를 못 받습니다.**
잃어버렸을 때만 하세요.

```bash
npx tauri signer generate -w "%USERPROFILE%\.bogyeol-release\bogyeol-updater.key" -f
```

비밀번호를 물으면 입력해 `PASSWORD.txt` 에도 적어 두고, 새로 나온 공개 키를
`tauri.conf.json` 의 `pubkey` 에 붙여 넣으세요. GitHub Secret 두 개도 함께 바꿔야 합니다.

> **비밀번호를 빈 값으로 두지 마세요.** PowerShell 에서 `$env:X = ""` 는 변수를
> 지우는 것과 같아서, 빌드가 "Decrypting updater signing key" 에서 비밀번호를
> 물으며 그대로 멈춥니다.

## 2. 처음 한 번 — GitHub 준비

### 2-1. 저장소 만들기

GitHub에서 **공개(Public) 저장소**를 하나 만듭니다. 이름은 `substitute-teacher-manager` 로 정했습니다.

> 비공개 저장소로는 자동 업데이트가 제대로 되지 않습니다. 업데이터가 파일을
> 받으려면 개인 토큰이 설치 파일 안에 들어가야 하는데, 그러면 누구나 꺼낼 수
> 있어 비공개의 뜻이 없어집니다.

### 2-2. 업데이트 주소 — 이미 되어 있음

`src-tauri/tauri.conf.json` 에 아래 주소가 들어가 있습니다. 저장소 이름을
바꾸면 이곳도 함께 고쳐야 합니다.

```json
"endpoints": [
  "https://github.com/lohemal/substitute-teacher-manager/releases/latest/download/latest.json"
]
```

### 2-3. 서명 키를 GitHub Secret 에 넣기

저장소 → **Settings → Secrets and variables → Actions → New repository secret**

| 이름 | 값 |
|---|---|
| `TAURI_SIGNING_PRIVATE_KEY` | `bogyeol-updater.key` 파일의 **내용 전체**를 복사해 붙여 넣기 |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | `PASSWORD.txt` 의 내용 |

파일 내용을 보려면:

```bash
type "%USERPROFILE%\.bogyeol-release\bogyeol-updater.key"
```

### 2-4. 코드 올리기

```bash
git init
git add .
git commit -m "보결 배정 시스템 첫 커밋"
git branch -M main
git remote add origin https://github.com/lohemal/substitute-teacher-manager.git
git push -u origin main
```

## 3. 새 버전 내보내기

### 3-1. 버전 올리기

두 곳의 버전을 **같게** 맞춥니다.

- `package.json` 의 `version`
- `src-tauri/tauri.conf.json` 의 `version`
- `src-tauri/Cargo.toml` 의 `version`

```bash
npm run version:set 0.2.0
```

### 3-2. 태그 올리기

```bash
git add .
git commit -m "v0.2.0"
git tag v0.2.0
git push origin main --tags
```

그러면 GitHub Actions 가 알아서

1. 타입 검사 · 화면 빌드 · 계산 로직 검사 · 서버 테스트를 돌리고
   (하나라도 실패하면 **릴리스를 만들지 않습니다**)
2. Windows 설치 파일(`.exe`)을 만들고
3. 개인 키로 서명하고
4. 릴리스에 설치 파일과 `latest.json` 을 올립니다

Actions 탭에서 진행 상황을 볼 수 있고, 보통 10~15분쯤 걸립니다.

### 3-3. 확인

릴리스 페이지에 이 네 파일이 있어야 합니다.

| 파일 | 무엇인가 | 없으면 |
|---|---|---|
| `bogyeol_0.2.0_x64-setup.exe` | 설치 파일 | 설치할 수 없다 |
| `bogyeol_0.2.0_x64-setup.exe.sig` | 서명 | 자동 업데이트가 서명 검증에서 막힌다 |
| `latest.json` | 업데이트 정보 | **자동 업데이트가 아예 동작하지 않는다** |
| `SHA256SUMS.txt` | 체크섬 | 직접 받은 파일을 확인할 수 없다 (없어도 설치는 됨) |

> **왜 파일 이름이 영문인가요?**
> 앱 이름은 한글(`보결 배정 시스템`)이라 만들어진 설치 파일도 한글 이름입니다.
> 그런데 GitHub는 첨부 파일 이름에서 한글을 떼어 내 `_0.2.0_x64-setup.exe` 처럼
> 뜻 없는 이름이 됩니다. 그래서 올릴 때만 `bogyeol_...` 로 바꿉니다.
> **설치한 프로그램의 이름은 그대로 한글**입니다 (시작 메뉴·앱 목록).

서명이 없거나 비어 있으면 워크플로가 릴리스를 만들지 않고 멈춥니다.
반쪽짜리 릴리스가 올라가는 일은 없습니다.

## 4. 다른 학교에 나눠 줄 때

### 처음 설치

릴리스 페이지 주소를 알려 주고 `...setup.exe` 를 내려받아 실행하게 하면

새 버전을 받습니다. 자료(자료 파일·백업)는 그대로 남습니다.

## 5. 업데이트가 어떻게 도는가 (고칠 때 참고)

화면 코드는 `src/features/admin/UpdateCard.tsx` 하나입니다. 흐름은 이렇습니다.

```js
const update = await check()        // 새 버전이 없으면 null
await update.download(onProgress)   // 내려받기 (진행률)
await update.install()              // 설치 — 여기서 앱이 닫힌다
```

### `relaunch()` 를 부르면 안 된다

Windows에서 `install()` 은 **돌아오지 않습니다.** 플러그인이 설치 프로그램을
`/P /UPDATE /R` 로 띄운 뒤 `std::process::exit(0)` 로 앱을 스스로 끝냅니다.
설치가 끝나면 NSIS가 `/R` 옵션에 따라 앱을 다시 켭니다.

그래서 화면에서 따로 `relaunch()` 를 부르면 **방금 뜬 설치 프로그램과 경쟁**합니다.
앱이 먼저 다시 켜지면 NSIS가 실행 중인 파일을 바꾸지 못하고 포기하므로,
겉으로는 "업데이트했는데 그대로"인 상태가 됩니다. v0.1.2까지 이 문제가 있었습니다.

### 확인만으로 설치하지 않는다

수업 중에 프로그램이 갑자기 닫히면 안 되므로, `check()` 는 알려 주기만 하고
사람이 [업데이트 시작]을 눌러야 `download()` → `install()` 로 넘어갑니다.

### 한 번에 끝나야 한다

`check()` 가 돌려준 `Update` 객체 하나로 설치까지 갑니다. 앱을 다시 켠 뒤
다시 확인해야 하는 구조가 되면 안 됩니다.

## 6. 자주 겪는 문제

**[업데이트 확인]을 눌렀는데 "업데이트 정보를 찾지 못했습니다"**
아직 릴리스가 없거나, `endpoints` 주소가 틀렸거나, `latest.json` 이 릴리스에
올라가지 않은 경우입니다. 릴리스 페이지에서 파일 세 개를 확인하세요.

**"서명이 맞지 않아 설치하지 않았습니다"**
`tauri.conf.json` 의 공개 키와 GitHub Secret 의 개인 키가 짝이 아닙니다.
키를 새로 만들었다면 둘 다 바꿔야 합니다.

**릴리스가 올라갔는데 정말 되는지 미리 보고 싶다**
업데이터가 보는 주소를 그대로 열어 보면 됩니다. 앱을 설치하지 않아도 확인됩니다.

```bash
curl -sL https://github.com/lohemal/substitute-teacher-manager/releases/latest/download/latest.json
```

`version` 이 새 버전인지, `signature` 가 비어 있지 않은지, `url` 이 실제로
받아지는지 세 가지를 보세요.

**Actions 가 빨간불**
Actions 탭에서 실패한 단계를 여세요. 테스트에서 막힌 것이면 코드를 고쳐야
하고, `tauri-action` 에서 막힌 것이면 Secret 이 안 들어갔을 가능성이 큽니다.

**설치했는데 예전 자료가 안 보임**
자료는 `%APPDATA%\kr.school.bogyeol\` 에 있고 프로그램과 따로 있습니다.
업데이트로 지워지지 않습니다. 설정 → 자료 저장 위치에서 확인하세요.
